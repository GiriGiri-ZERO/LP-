# 司令塔：指示 → 即レス化 手順書（ポーリング → GitHubトリガー）

> ゴール：和代さんが指示を出した「その瞬間」にクロードが起動して実作業し、結果を返す。
> いまの「15分ごとに見に来る（Routine）」の待ち時間を撤去する。
>
> ※ この手順は **Vault/cloud 側のリポジトリ**で実施します（`build_dashboard.py` / `cloud/` / Worker がある側）。

---

## 全体像

```
和代さんが指示を送信（PWA / 入力フォーム）
      │
      ▼
Cloudflare Worker  ──(GitHub API)──▶  GitHub に Issue 作成
      │                                 本文「@claude <指示>」← この瞬間に発火
      │                                       │
      │                                       ▼
      │                         Claude（GitHub App）がメンション検知 → 即起動
      │                                 ・ファイル更新／ダッシュボード再生成／デプロイ
      │                                 ・結果を Issue にコメント
      │                                       │
      └──(Issueコメントを取得)◀───────────────┘
                  │
                  ▼
        和代さんに返信を表示
```

ポイント：**KVに溜めて15分待つ部分を撤去**し、「送信＝Issue作成」で即トリガーに置き換える。

---

## ⚠️ 最初に：安全チェック（最重要）

GitHubに上げる前に必ず：

1. **鍵・トークンは絶対にコミットしない。** 以下を `.gitignore` に入れる：
   ```gitignore
   .secrets/
   *.secret
   .dev.vars
   board.config.js        # TOKEN を含むなら除外（→ サンプルだけ board.config.example.js を置く）
   .wrangler/
   node_modules/
   ```
2. **Obsidian Vault 丸ごとは上げない。** ボード/cloud だけの**専用リポジトリ**を作る（個人メモの流出防止）。
3. リポジトリは **private** にする。
4. push 前に既存ファイルにトークンが残っていないか確認（`git grep -i token` 等）。
5. Worker側の鍵は **`wrangler secret`** に置いたまま（リポジトリには入れない）。

## 手順

### 1. ボード/cloud を専用リポジトリにして push

```bash
cd /Users/apple/Documents/Obsidian\ Vault/事業/司令塔ボード   # 例：ボードのフォルダ
git init
# 上の .gitignore を置いてから
git add .
git commit -m "init: 司令塔ボード/cloud"
# GitHubで private リポジトリ（例 vault-board）を作成しておき：
git remote add origin git@github.com:girigiri-zero/vault-board.git
git push -u origin main
```

### 2. Claude の GitHub App をインストール

- https://github.com/apps/claude を、作った **vault-board リポジトリにインストール**。
- これで Issue / PR 内の `@claude` メンションにクロードが反応し、セッションが即起動するようになる。

### 3. Worker に「送信 → Issue作成」を追加

```js
// 和代さんの指示を受け取って GitHub Issue を作る = 即トリガー
async function sendToClaude(instruction, env) {
  const res = await fetch(
    `https://api.github.com/repos/${env.REPO}/issues`, // 例 "girigiri-zero/vault-board"
    {
      method: "POST",
      headers: {
        "Authorization": `Bearer ${env.GITHUB_TOKEN}`, // wrangler secret
        "Accept": "application/vnd.github+json",
        "User-Agent": "shireito-board",
      },
      body: JSON.stringify({
        title: `指示: ${instruction.slice(0, 50)}`,
        body: `@claude ${instruction}\n\n（和代さんからの指示。実作業まで行い、完了したらこのIssueにコメントで報告してください）`,
        labels: ["和代", "司令塔"],
      }),
    }
  );
  const issue = await res.json();
  return issue.number; // ← 返信を拾うために保存しておく
}
```

シークレット登録：
```bash
cd 事業/司令塔ボード/cloud
wrangler secret put GITHUB_TOKEN   # repo権限つきのトークンを入力（値はコミットしない）
```
`wrangler.toml` の `[vars]` に `REPO = "girigiri-zero/vault-board"` を追加。

### 4. クロードの返信を和代さんに戻す

**A案（簡単・ポーリング）**：和代さんの画面が、保存した `issue.number` のコメントを数十秒おきに取得して表示。
```js
async function fetchReply(issueNumber, env) {
  const res = await fetch(
    `https://api.github.com/repos/${env.REPO}/issues/${issueNumber}/comments`,
    { headers: {
        "Authorization": `Bearer ${env.GITHUB_TOKEN}`,
        "Accept": "application/vnd.github+json",
        "User-Agent": "shireito-board",
    }});
  const comments = await res.json();
  return comments.map(c => c.body); // 最新のものを表示
}
```

**B案（即時・Webhook）**：GitHub の Webhook（`issue_comment` イベント）を Worker で受け、KV/D1 に保存 → 和代さんの画面へプッシュ。完全リアルタイムにしたいならこちら。

> まずは **A案**で十分。体感が遅ければ B案へ。

### 5. 既存の「15分 Routine」を止める／間引く

- いまの定期実行（`/schedule` / Routines）が KV inbox をポーリングしているはず。
- 上の即トリガーに移行したら、**この Routine は停止**するか、保険として長め（1時間など）に間引く。

## メモ

- 任意の外部Webhookから直接Claudeセッションを起こすAPIは無い（2026-06時点）。だから **GitHubのIssue/メンションを即時トリガーのバスに使う**のがこの設計の肝。
- 実作業（再生成・デプロイ）は従来どおりフルに可能。
- 鍵は最後まで `wrangler secret` / `~/context/.secrets/` に置き、リポジトリには入れない。
